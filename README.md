# Портал настільної кампанії

Готова основа для власного сайту кампанії: бібліотека матеріалів, журнал партій, NPC, мапа з позначками, нотатки майстра й довідники. Це **окрема порожня копія**: вона не підключена до акаунтів, бази чи сайту іншої кампанії.

## Що зберігається де

| Місце | Вміст |
| --- | --- |
| Цей репозиторій | Код сайту, порожня структура бази, HTML-довідники та власні векторні заглушки |
| Cloudflare Worker | Опублікований сайт і серверні перевірки доступу |
| Cloudflare D1 | Партії, нотатки, NPC, позначки та дозволені пошти **вашої** кампанії |
| Firebase Authentication | Вхід через Google або пошту з паролем; не зберігає історію партій |

GitHub сам не запускає цей сайт. Для публікації кожному власнику потрібні власні Cloudflare Worker, база D1 і Firebase-проєкт. Не підставляйте чужий `database_id`, Firebase Project ID чи пошту власника.

## Що є в порожній копії

- Порожній журнал: акти, арки й партії створює майстер на сайті.
- Порожні NPC, позначки мапи й нотатки майстра.
- Три нейтральні профілі «Персонаж 1–3» **без прив’язаних пошт**. Майстер може змінити їхні назви й додати пошти в адмінці.
- Векторна мапа-приклад, оригінальні заглушки обкладинок і місце для власної книги кампанії.
- HTML-довідники: Консоль Jockie, Foundry VTT, Академія Сільвермуна, «Дроу під сонцем» і довідник цін. Їх потрібно один раз записати до нової D1 командою `npm run content:local` або `npm run content:remote`.

Вхід залишається закритим за замовчуванням: майстром стає лише адреса `OWNER_EMAIL`; гравців майстер додає до списку дозволених пошт. Просто знати адресу сайту недостатньо, щоб читати приватні дані.

## Локальний перегляд

Потрібні Node.js 22.12+ і npm. У папці репозиторію:

```powershell
npm ci
Copy-Item .dev.vars.example .dev.vars
npm run db:local
npm run content:local
npm run build
npm run preview
```

Відкрийте `http://127.0.0.1:8790/`. Локальний режим у `.dev.vars` створює **тільки на вашому комп’ютері** тестового майстра й гравця; він не повинен потрапити в опублікований Worker. Локальна база відділена від майбутньої робочої бази. Щоб виконати перевірки, запустіть `npm test`.

## Підготовка власної кампанії

1. [Налаштуйте власні акаунти й опублікуйте сайт](DEPLOYMENT.md).
2. [Змініть назву, обкладинку, книгу та мапу](docs/CUSTOMIZE.md). Там описані розміри мапи, автоматичне масштабування, нарізання великого зображення й масштаб лінійки.
3. [Створіть окремий репозиторій GitHub](docs/PUBLISH.md), якщо хочете зберігати власну версію або передати шаблон іншим.

Оригінальні PDF та ілюстрації чужої кампанії сюди не входять. Про походження заглушок і перевірку матеріалів перед публічним поширенням читайте в [ART_CREDITS.md](docs/ART_CREDITS.md).

## Безпека й оновлення

Файли `.env.production.local`, `.dev.vars`, `private/`, `dist/` і `node_modules/` не додаються до Git. Пароль власника Cloudflare та `OWNER_EMAIL` не слід записувати до коду. Звичайна публікація нової версії Worker не очищує D1. Перед змінами структури бази збережіть її копію.

Автоматичної публікації чи фонових завдань у GitHub немає: збірку й тести запускайте вручну перед оновленням. Жодної платної можливості для цього шаблону не потрібно. Якщо якийсь сервіс запропонує картку або платний план, зупиніться й перевірте його налаштування, перш ніж продовжувати.
