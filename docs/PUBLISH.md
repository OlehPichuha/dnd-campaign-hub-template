# Як розмістити цю копію на GitHub

GitHub зберігатиме код та історію версій; відвідувачі користуватимуться сайтом за адресою Cloudflare після окремого розгортання. Створення репозиторію саме по собі не публікує робочий сайт і не створює базу D1.

1. Перед відкритою публікацією перегляньте вміст `content/library/` і права на тексти чи сторонні назви. Призначте ліцензію для коду, яку справді хочете дати іншим. Поки ліцензію не обрано, не обіцяйте вільного повторного використання всього вмісту.
2. Перевірте, що в копії немає `.env.production.local`, `.dev.vars`, `private/`, резервних копій, особистих фотографій, PDF чи вашого Google Drive URL. Ці шляхи ігноруються Git, але перегляньте список файлів перед першим завантаженням.
3. На GitHub створіть **новий порожній репозиторій**. Не робіть fork оригінальної приватної кампанії та не копіюйте її стару історію комітів.
4. Ця локальна копія вже має окрему історію Git, яка починається лише з очищеного шаблону. Під’єднайте до неї адресу нового репозиторію та завантажте гілку `main`. Не під’єднуйте репозиторій оригінальної кампанії.
5. Після завантаження відкрийте репозиторій у приватному вікні браузера, якщо він публічний, і ще раз перегляньте файли. Щоб отримати робочий сайт, новий користувач проходить [DEPLOYMENT.md](../DEPLOYMENT.md) **у власних** Cloudflare і Firebase.

Якщо репозиторій зробити публічним, усі файли й історію комітів зможе читати кожен. Тому спочатку потрібно очистити копію, а вже потім робити її публічною. Поточний робочий сайт і його база від такої копії не змінюються.
