# Власні акаунти й публікація сайту

Ця інструкція створює **новий** сайт. Репозиторій не містить чинної бази кампанії, підключення до її Firebase чи паролів. Для першого запуску використовуйте власні акаунти Cloudflare та Firebase. Їхні безкоштовні плани мають квоти, які можуть змінюватися; не вмикайте платні функції та не прив’язуйте картку, якщо цього не планували.

## 1. Перевірте копію локально

Виконайте команди з [README](README.md). Переконайтеся, що відкриваються бібліотека, порожній журнал, NPC, мапа й довідники. Локальний тестовий вхід діє лише для `localhost`/`127.0.0.1`.

## 2. Створіть Firebase-проєкт

У Firebase створіть власний проєкт, зареєструйте Web app і ввімкніть Authentication → Sign-in method → Google. За потреби увімкніть Email/Password: цей спосіб зручний у вбудованому браузері Telegram. Email link не потрібен. Укажіть свою контактну пошту для екрана Google-входу.

Скопіюйте `.env.example` у `.env.production.local` і заповніть чотири значення `VITE_FIREBASE_*` з налаштувань вашого Firebase Web app. Це конфігурація вебклієнта, а не пароль. Файл з вашими значеннями залишається поза Git.

## 3. Створіть власну базу D1 і Worker

Увійдіть у Wrangler під **власним** Cloudflare-акаунтом, потім створіть нову базу:

```powershell
npx wrangler login
npx wrangler d1 create campaign-template-db
```

Команда поверне `database_id`. Впишіть його у `wrangler.jsonc` замість нулів. Там само замініть `name` на унікальну назву свого Worker, а `FIREBASE_PROJECT_ID` — на ID свого Firebase-проєкту. Назва D1 `campaign-template-db` у прикладі збігається з командами в `package.json` і `scripts/sync-library-content.mjs`; якщо змінюєте її, змініть у всіх трьох місцях.

Після цього створіть порожні таблиці та завантажте готові HTML-довідники **у свою нову базу**:

```powershell
npm run db:remote
npm run content:remote
```

Ці команди не імпортують чиїсь партії. Не запускайте їх з ID чужої бази.

## 4. Опублікуйте сайт і задайте власника

```powershell
npm run deploy
npx wrangler secret put OWNER_EMAIL
```

У другій команді введіть свою підтверджену пошту Firebase. Поки `OWNER_EMAIL` не заданий, сервер не допускає відвідувачів. Додайте hostname вашої нової адреси `*.workers.dev` до Firebase Authentication → Settings → Authorized domains.

За бажанням налаштуйте книгу кампанії: `npx wrangler secret put CAMPAIGN_BOOK_URL`. Укажіть власне HTTPS-посилання на Google Drive або інший файл. Кнопка книги з’явиться тільки для майстра й відкриватиме посилання в новій вкладці. Права доступу до файла додатково задаються на самому Google Drive. PDF не потрібно складати в публічний репозиторій.

## 5. Перевірте опубліковану версію

Увійдіть своєю адресою майстра, додайте пошту гравця в адмінці та перевірте його перегляд. Сторонній акаунт не повинен пройти. Перевірте карту на телефоні й ПК, а також книгу в новій вкладці, якщо її додали.

Для наступного оновлення коду запустіть `npm run build`, `npm test`, а потім `npm run deploy`. Додавання записів через сайт змінює D1, а не GitHub. Перед великим оновленням бази зробіть резервну копію:

```powershell
npx wrangler d1 export campaign-template-db --remote --output private/backup.sql
```

Складений у `private/` файл не потрапить до Git. Не публікуйте його: там будуть усі записи вашої кампанії.
